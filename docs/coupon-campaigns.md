## 使用

1. 已建档活动可分别按门店、活动名称、开始时间、结束时间筛选；日期条件用于筛选档期完整落入所选区间的活动。新建活动时填写名称、门店、起止日期、券种（如 B,E,H,M）及 ERP 档期编码（七夕中心为 2205）。不会自动替用户创建正式活动。
2. 保存后归属字段固定。相同门店、相同券种、相交日期不允许重复建档；第一版没有删除或修改归属的接口。可以编辑名称、说明及ERP档期编号；变更ERP编号会清除旧规则快照。
3. 查看券种、当前会员等级分层、持券会员、关联小票、品牌汇总、质量提示。点击会员号钻取其关联小票。
4. 从柜位 ODS 读取 ERP 收券规则摘要快照。它是采集时已审核配置，不是逐笔 POS 命中证据；不按宣传门槛或零值规则判违规。页面读取不触发 ERP 同步。
5. 导出 Excel 包含全量结果，不受页面分页或会员筛选影响；卡号按文本导出。
6. 销售增长试算在页面和 Excel 中同时列明活动期，以及前4周每一组同星期基准日期，避免只显示“前4周”而无法核对实际取数日期。

## 口径

- 用首次发券的门店、券种、有效期归属。有效期必须包含于活动起止日期，允许提前发券。按资产序号去重，排除同资产更早的首次发券。
- 核销跟随已归属资产，不从后续销售/退货重判来源。活动期间核销和冲正分别计入券金额。
- 连带销售是用券小票销售收入，不代表增量销售；同票多券/多持券人按本活动净核销金额分摊，总额去重。
- 退货优先按 salehead.ybillno 关联原票，不依赖是否退券。缺原票时，仅用同一退货小票匹配的本档退券日志补充关联，并标记。已有原票但不属于本档的，不补入。
- 活动后退货不进入本期或下一活动的关联销售。会员“本人本店本期净销售”是独立的日历期间指标，包含其本期全部销售退货，不能代替本档关联销售。
- 持券会员与小票登记会员分开；不一致仅为核查线索，缺小票会员单列。会员等级为查询时点等级，不声称活动时点快照。
- 平均单票 = 净连带销售 / 核销销售小票数，分母不扣退货票数。资产数、流水数不当作券面张数。
- 未支持的转移、延期、作废等列质量提示，缺失/歧义小票不会猜测匹配。超过10万行拒绝生成，不默默截断。
- 金额汇总保留 Decimal 精度，展示/导出四舍五入到分，分摊行可能存在尾差。

### 自动同步路径

- 迁移 `n3c4d5e6f7a8`（前置 `m2b3c4d5e6f7`）新增 `ods.campaign_rule_stage` 和事务发布触发器。
- `campaign_rule_schedule.scheduled_task()` 生成PAPI任务：单条Oracle SELECT流式读取单据头、明细及末尾一条校验清单。两表处于同一Oracle语句快照，行数、行哈希合计由该语句计算；即使源表全空，也会输出零行清单。
- 必须使用Oracle ResultSet流式读取，不能改成逐页重查、watermark或断点续传。按行类型＋源唯一键排序，清单最后到达；批次名由门店＋ERP档期＋Oracle语句时间组成，同秒重复运行会由主键拒绝而非覆盖。
- 柜位库触发器在清单入库时核对完整性、哈希合计、同源时点、门店、档期、主键和关联单头。全部通过才在同一事务写入两张正式ODS表、标记已发布、切换当前批次；失败保留旧批次，PAPI任务报错。较旧源时点批次不得回退当前指针。
- `POST/PUT /api/database-tasks` 使用顶层 `scheduleEnabled`、`scheduleType`、`scheduleTime`。嵌套 `schedule` 是模块专用创建协议，在当前普通更新入口会被忽略。必须回读 `enabled`、`schedule_enabled` 和 `next_run_at` 才能宣布定时生效。
- 定时任务只负责规则ODS，不改活动建档、不替换已保存的活动规则快照、不改销售/会员/发券日志。页面“从ODS读取规则快照”取已校验的最新批次，已导出报告保持原快照证据。

运维脚本 `python_app/sync_campaign_rule_ods.py` 使用 papi-etl 技能的安全客户端（可用 `--papi-client` 指定路径），不保存密钥：

```sh
# 获得建表/配置授权后准备禁用任务；下列编号必须经当次 resources 核对
.venv/bin/python python_app/sync_campaign_rule_ods.py prepare --store 601 --pid 2205 --source-id 7 --target-id 4 --confirm-write
# 预览脚本输出的两个任务ID，核对字段/范围，再经授权通过PAPI run执行
# 两个任务均完整成功并检查详细日志后，校验并发布指定批次
.venv/bin/python python_app/sync_campaign_rule_ods.py publish --batch <批次UUID> --source-id 7 --target-id 4 --confirm-write
```

统一网关通过 `POST /api/database-tasks` 配置任务；不要经统一网关转发模块专用的 `/api/etl/ai/tasks`。当前服务器对此返回403，模块入口另需专用授权，不能混用密钥。

快照记录页面读取时间、ODS采集时间、校验批次、规则模式、各门槛及收券金额、起止日期、规则行数/单据数。缺表/尚未同步返回明确503并保留旧快照；已校验批次筛选后确无规则才返回空数组。快照刷新后可导出ODS批次和时间。这里的采集不是活动当时的历史配置快照，不支持据此反推当时POS实际命中规则。

第一版不提供 POS 规则覆盖优先级、逐笔门槛合规判断、CRM超领判断、AI总结及ROI。
