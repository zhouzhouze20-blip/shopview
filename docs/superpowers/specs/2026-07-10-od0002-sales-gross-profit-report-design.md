# OD0002 门店销售毛利汇总表设计

## 目标

在 ShopView 的“销售管理 → 报表”下新增“OD0002 门店销售毛利汇总表”。报表支持在线查看和 Excel 导出，并严格复用当前用户的销售数据权限。

第一版提供六个汇总层级：分店、部门、区域、品类、柜组、楼层。参考文件中的“大类”暂不实现。

## 用户体验

页面顶部提供：

- 本期开始日期和结束日期；
- 同期开始日期和结束日期，只读并自动取上一年相同月日；
- 门店筛选，支持“权限内全部门店”和单个门店；
- 查询、重置和导出 Excel 操作。

结果区使用六个标签页：

1. 分店
2. 部门
3. 区域
4. 品类
5. 柜组
6. 楼层

每个标签页展示销售收入、毛利额和毛利率的本期、同期与同比。金额按万元展示；销售收入和毛利额同比使用 `本期 / 同期 - 1`；毛利率同比使用本期毛利率减同期毛利率，并按百分点展示。

选择全部门店时，除分店页外的其他页面保留门店列，防止不同门店的同名部门、区域、品类、柜组或楼层被合并。选择单门店时，在线页面可以隐藏重复门店列，但接口和导出仍保留门店键。

柜组页可能包含较多行，应支持分页或虚拟滚动；所有页面应固定多级表头。

## 导航与权限

导航入口位于“销售管理 → 报表”，与“商品销售明细”并列，显示名称为“OD0002 门店销售毛利汇总表”。入口沿用 `sales.view` 权限。

后端先加载现有销售业务数据范围，再将允许的门店、部门和柜组范围直接加入聚合查询。未授权数据不得返回前端。页面合计与 Excel 合计只覆盖当前用户可见的数据。

权限行为：

- 仅有部门范围的用户只能看到授权部门，并且六个标签页的汇总均由这些部门的数据计算；
- 拥有门店级范围的用户可以查看该门店全部部门；
- 拥有多个门店范围的用户可以选择权限内全部门店或单个门店；
- 导出必须复用相同查询条件和权限范围，不能绕过在线查看权限。

## 数据来源与关联

事实表为 `salegoodslist`：

| 含义 | 字段或计算 |
| --- | --- |
| 门店 | `sglmarket` |
| 记账日期 | `sglhsrq` |
| 柜组编码 | `sglmfid` |
| 销售收入 | `SUM(sglxssr)` |
| 毛利额 | `SUM(sgln2)` |
| 毛利率 | `SUM(sgln2) / NULLIF(SUM(sglxssr), 0)` |
| 经营方式 | `sglwmid` |

销售柜组通过 `salegoodslist.sglmfid = manaframe.mfcode` 关联柜组主数据。`manaframe` 提供：

- `mfcode` / `mfcname`：柜组编码、名称；
- `mfpcode`：上级部门编码，再关联上级 `manaframe` 记录取得部门名称；
- `mflc`：楼层编码；
- `mfchr1`：区域品类字典的品类编码。

区域和品类通过 `manaframe.mfchr1 = area_category.category_code` 关联，并从同一条字典记录取得：

- `area_category.area_code`；
- `area_category.area_name`；
- `area_category.category_code`；
- `area_category.category_name`。

`manaframe.mfchr2` 是更细的七位分类编码，第一版 OD0002 不使用它关联 `area_category`。

楼层名称使用以下映射：

| 编码 | 名称 | 编码 | 名称 |
| --- | --- | --- | --- |
| 01 | BF | 11 | 10F |
| 02 | 1F | 12 | 11F |
| 03 | 2F | 13 | 12F |
| 04 | 3F | 14 | 13F |
| 05 | 4F | 15 | 14F |
| 06 | 5F | 16 | 特卖 |
| 07 | 6F | 17 | 微商城 |
| 08 | 7F | 18 | 15F |
| 09 | 8F | 19 | 16F |
| 10 | 9F |  |  |

楼层 `00` 不进入报表。

## 过滤口径

所有六个层级使用相同基础数据集：

1. 时间以 `salegoodslist.sglhsrq` 为准；
2. 排除 `salegoodslist.sglwmid = '5'` 的租赁数据；
3. 排除 `manaframe.mflc = '00'`；
4. 排除参考报表指定的二级部门：
   - `6010115`, `6010108`, `6010109`, `6010110`, `6010202`, `6010205`
   - `6020105`, `6020107`, `6020109`, `6020202`, `6020205`
   - `6030108`, `6030109`, `6030111`, `6030202`, `6030205`
5. “其他类别区域”通过区域名称识别并排除；名称比较前后去空格；
6. 应用当前用户的门店、部门和柜组数据范围；
7. 用户选择单店时再应用门店筛选。

## 后端结构

新增 OD0002 专用报表接口。接口接收本期起止日期和可选门店，自动生成去年同期日期。后端从同一个权限过滤后的基础数据集生成六个维度的本期、同期聚合结果，以保证各页合计一致。

接口响应包含：

- 本期和同期日期；
- 当前门店筛选；
- 六个维度的数据行；
- 每个维度的合计；
- 数据质量提示，例如未匹配的区域品类或楼层编码；
- 结果生成时间。

查询应在数据库完成聚合，不把明细销售记录传给前端。多门店结果的分组键必须包含门店标识。

Excel 导出使用同一报表服务和同一权限上下文，避免在另一个查询中复制口径。导出端点返回服务器生成的 `.xlsx` 文件。

## Excel 输出

导出文件包含：

1. 分店
2. 部门
3. 区域
4. 品类
5. 柜组
6. 楼层
7. 报表说明

工作表样式尽量匹配参考文件，包括标题、日期范围、多级蓝色表头、万元金额、百分比、合计行和冻结表头。第一版不创建“大类”工作表。

“报表说明”必须记录日期口径、收入和毛利字段、租赁排除规则、楼层 `00` 排除规则、排除部门列表，以及“合计仅包含当前用户权限范围”的说明。

## 空值与异常处理

- 无 `sales.view` 权限：返回权限错误，页面显示“无权查看销售报表”；
- 查询成功但没有数据：返回空集合和零行状态，页面显示“当前条件下无数据”；
- 同期收入为零：销售收入同比为空，不显示无穷大；
- 同期毛利为零：毛利同比为空；
- 本期或同期收入为零：对应毛利率为空；
- 区域品类字典未匹配：归入“未匹配”，同时在质量提示中返回数量；
- 未识别楼层编码：归入“未匹配”，同时返回质量提示；
- 数据库或导出失败：返回可识别的错误信息，前端不下载空文件。

## 测试策略

后端测试覆盖：

- 同期日期自动回退一年，包括闰年边界；
- 收入、毛利、毛利率、同比和百分点变化公式；
- 租赁、楼层 `00`、指定部门和“其他类别区域”排除；
- `manaframe`、`area_category` 和楼层名称关联；
- 多门店同名维度不混合；
- 部门权限对六个层级和合计均生效；
- 字典未匹配和空数据响应；
- Excel 工作表名称、表头、合计及说明页。

前端测试覆盖：

- 菜单入口和权限可见性；
- 本期变化后自动计算同期；
- 全部门店和单门店筛选；
- 六个标签页渲染；
- 空状态、无权限和接口错误；
- 导出使用当前筛选条件。

## 不在第一版范围内

- “大类”标签页和“大类”Excel 工作表；
- 自定义同期日期；
- 定时报表或邮件发送；
- 新建预聚合表或物化视图；
- 修改现有销售明细的收入、毛利或经营方式定义。
