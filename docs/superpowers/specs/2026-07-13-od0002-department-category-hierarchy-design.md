# OD0002“部门（含品类）”汇总设计

## 目标

在现有“OD0002 门店销售毛利汇总表”中新增独立汇总层级“部门（含品类）”，同时提供在线页签和 Excel 同名工作表。新层级按“门店 → 部门 → 区域 → 品类”保留完整组织关系，展示品类明细、区域小计、部门小计和总合计。

原有“分店、部门、区域、品类、柜组、楼层”六个层级及其接口口径、页面展示和 Excel 工作表保持不变。

## 入口与顺序

在线页签顺序调整为：

1. 分店；
2. 部门；
3. 部门（含品类）；
4. 区域；
5. 品类；
6. 柜组；
7. 楼层。

Excel 工作表顺序与页面一致，最后仍为“报表说明”：

1. 分店；
2. 部门；
3. 部门（含品类）；
4. 区域；
5. 品类；
6. 柜组；
7. 楼层；
8. 报表说明。

## 数据粒度与聚合

新增后端维度键 `department_categories`。明细行的唯一业务粒度为：

```text
门店编码 + 部门编码 + 区域编码 + 品类编码
```

该维度直接使用 OD0002 已有的权限过滤后的 `base` 数据集，不另建统计 SQL，也不从现有“部门”“区域”“品类”三个汇总结果进行前端拼接。

数据库新增一组聚合结果，保留以下标识字段：

- `store_code`、`store_name`；
- `department_code`、`department_name`；
- `area_code`、`area_name`；
- `category_code`、`category_name`。

聚合指标继续使用 OD0002 现有字段和公式：

- 本期销售收入、同期销售收入、销售收入同比；
- 本期毛利额、同期毛利额、毛利额同比；
- 本期毛利率、同期毛利率、毛利率变化。

同比、毛利率及毛利率变化继续由公共指标归一化逻辑计算，避免新维度产生另一套公式。

## 组织关系与空值

部门来自柜组上级 `manaframe`；区域和品类来自现有 `manaframe.mfchr1 = area_category.category_code` 关联。新维度必须保留这些字段之间的同一事实行关系。

分组键必须包含门店编码，防止多门店下编码相同的部门、区域或品类被合并。部门、区域或品类缺少编码或名称时，沿用 OD0002 当前的“未匹配”展示和数据质量口径，不丢弃本来应保留的事实行。

现有过滤保持不变：

- 日期范围及自动计算的同期范围；
- `sglwmid = '5'` 的租赁排除；
- 楼层 `00` 排除；
- OD0002 已维护的部门排除列表；
- “其他类别区域”排除；
- 当前用户的门店、部门、柜组允许或拒绝范围；
- 用户当前选择的门店和部门条件。

## 响应结构

现有 OD0002 响应中的 `dimensions` 和 `totals` 增加：

```text
dimensions.department_categories
totals.department_categories
```

`dimensions.department_categories` 返回后端已经排好顺序的层级行，包含品类明细、区域小计和部门小计。每行除现有 `store_code`、`store_name` 和 `metrics` 外，包含 `row_type` 以及适用于该层级的部门、区域、品类编码和名称。

`totals.department_categories` 为当前权限和查询条件下所有品类明细的总合计。数据库只返回品类粒度的未舍入指标；后端公共归并函数从这些明细确定性生成区域小计、部门小计和总合计。页面和 Excel 直接消费同一响应结果，不在前端或工作簿生成器中重新计算小计。

现有六个维度的响应结构不变。

## 排序与层级行

数据按以下顺序展示：

1. 门店；
2. 部门，复用 OD0002 当前的部门显示顺序；
3. 区域编码和区域名称；
4. 品类编码和品类名称。

每个区域先展示所属品类明细，随后展示一行“区域小计”；一个部门的全部区域完成后展示“部门小计”；所有部门完成后展示“合计”。

层级行类型固定为：

- `category`：品类明细；
- `area_subtotal`：区域小计；
- `department_subtotal`：部门小计；
- `grand_total`：总合计，仅用于 `totals.department_categories` 的语义标识，不重复放入明细数组。

小计必须由未四舍五入的原始金额汇总后再格式化，不能把页面显示值相加。空数据时不生成虚假的区域或部门小计，只显示标准空状态。

## 在线页面

新增“部门（含品类）”页签，位于“部门”之后。表格列为：

1. 门店；
2. 部门；
3. 区域；
4. 品类；
5. 销售收入：本期、同期、同比；
6. 毛利额：本期、同期、同比；
7. 毛利率：本期、同期、变化。

选择“权限内全部门店”时显示门店列；选择单门店时可隐藏重复门店列，但分组键仍保留门店编码。

品类明细行展示完整编码和名称。为接近参考表的层级效果，同一门店、部门、区域的重复文字在连续明细行中只强调首行；区域小计和部门小计使用加粗与浅色背景区分。同比颜色、万元格式、百分比格式和正负值规则继续复用 OD0002 现有展示函数。

新页签复用现有查询条件、提交状态、加载状态、空数据状态、错误状态、权限状态和 Excel 导出按钮，不增加独立筛选条件。

## Excel“部门（含品类）”工作表

新增工作表名称为“部门（含品类）”，放在“部门”和“区域”之间。标题、日期范围、蓝色多级表头、冻结窗格和数字格式沿用 OD0002 现有工作簿样式。

前四组标识列改为：

- 门店；
- 部门；
- 区域；
- 品类。

每个标识使用一个单元格，第一行显示名称、第二行显示编码，与在线表格当前“名称 + 编码”的展示方式一致。这样工作表仍为四个标识列加九个指标列，共十三列。指标列保持销售收入、毛利额、毛利率各三列。

行结构按照参考格式输出：

- 品类明细行；
- 区域小计行；
- 部门小计行；
- 工作表末尾总合计行。

连续层级可留空重复的上级名称以增强可读性，但不得合并会影响筛选或复制的跨行单元格。小计行加粗并使用浅色填充。工作表继续防护以 `=`, `+`, `-`, `@` 开头的文本，避免被 Excel 当作公式执行。

Excel 使用在线接口同一份报表结果和同一权限上下文，不执行第二套业务查询，也不重新汇总页面已经取得的层级行。

## 错误处理

- 无 `sales.view` 权限：行为与现有 OD0002 一致；
- 查询成功但新维度无数据：页签显示“当前条件下无数据”，Excel 仍生成有效表头和合计结构；
- 部门、区域或品类未匹配：保留行并显示“未匹配”，同时沿用现有质量提示；
- 同期值为零：同比显示为空，不显示无穷大；
- Excel 生成失败：沿用现有导出失败提示，不下载空文件。

新增维度失败不得改变现有六个维度的统计口径；实现和测试应把新维度作为 OD0002 同一次查询及响应构造的一部分，避免部分成功的混合响应。

## 测试策略

后端测试覆盖：

- SQL 按门店、部门、区域、品类四级键聚合；
- 相同品类编码位于不同部门或门店时不合并；
- 当前部门筛选和业务权限对新维度生效；
- 本期、同期、同比、毛利率公式与现有维度一致；
- 区域小计、部门小计和总合计等于品类明细的未舍入汇总；
- 未匹配组织仍保留并进入现有质量提示；
- 现有六个维度的响应保持兼容。

前端测试覆盖：

- 页签名称、位置和维度键；
- 门店、部门、区域、品类列；
- 明细、区域小计、部门小计和总合计的顺序与样式；
- 多门店显示门店列、单门店隐藏重复门店列；
- 金额、同比、毛利率及颜色格式；
- 加载、空数据、失败和未查询状态；
- 原有六个页签不受影响。

Excel 测试覆盖：

- 工作表名称和顺序；
- 标题、日期、表头、冻结窗格和数字格式；
- 品类明细、区域小计、部门小计和总合计；
- 页面与 Excel 使用相同明细和合计；
- 公式型文本转义；
- 空数据仍能生成有效工作表；
- 原有工作表内容和“报表说明”保持兼容。

## 验收方式

选择一个门店和一个部门的短日期范围进行核对：

1. “部门（含品类）”内所有品类本期、同期销售之和等于该部门小计；
2. 部门下各区域小计之和等于部门小计；
3. 新页签的部门小计等于原“部门”页签对应部门；
4. 同一条件下新页签总合计等于原 OD0002 总合计；
5. Excel“部门（含品类）”与在线页签逐行、小计和总计一致；
6. 多门店查询时，各单店结果之和等于“权限内全部门店”结果；
7. 验收记录区分自动化测试、ShopView 页面和 Excel 导出的证据。

## 不在本次范围内

- 修改原“部门”“区域”或“品类”的聚合粒度；
- 删除或重命名现有页签和工作表；
- 新增“大类”维度；
- 修改 OD0002 销售收入、毛利额、毛利率、同期或权限口径；
- 新增筛选条件或改变现有日期、门店、部门筛选交互。
