# 活动分析门店筛选设计

## 背景

“通用活动分析”当前同时提供“活动搜索”和“活动档期”选择，并在“活动档期券”范围下依赖单个 `activity_id` 查询。业务希望移除这两个控件，新增门店筛选，并将“活动档期券”调整为按门店与日期汇总全部活动档期券。

## 目标与范围

- 删除筛选区中的“活动搜索”输入框、搜索按钮和“活动档期”下拉框。
- 新增“门店”下拉框，默认值为“全部有权限门店”。
- “活动档期券”不再依赖单个活动档期，按分析范围、门店、开始日期和结束日期汇总。
- 门店条件统一作用于页面总览、卡券汇总、卡券流水、部门/柜组下钻及数据质量。
- 门店选项和查询结果都受当前用户业务数据权限约束。
- 不删除后端既有 `activity_id` 参数，避免影响其它调用方；“通用活动分析”页面不再传递该参数。
- 不修改“积分活动核对”“中心星钻会员”等其它活动分析子页面。

## 页面设计

筛选区保留以下控件：

1. 分析范围。
2. 开始日期。
3. 结束日期。
4. 门店。
5. 刷新。

门店下拉框展示“门店名称”，可同时附带门店编码帮助识别。默认“全部有权限门店”；用户选择具体门店后立即刷新当前分析及后续下钻数据。

页面不再请求 `/api/activity-analysis/activities`，也不再维护 `keyword`、`activityId` 和活动列表自动选择状态。查询启用条件不再依赖 `activityId`。

原先用于展示单个活动编码、门店、活动期和关联金额的活动信息卡删除。其位置改为统一范围说明，明确当前分析范围、门店和日期，避免用户误以为结果仍对应单个活动档期。

## 接口与权限设计

新增权限范围内的门店选项接口：

```text
GET /api/activity-analysis/store-options
```

接口要求 `activity_analysis.view` 权限，并结合 `load_business_scope(..., fallback_resource_code="sales")` 返回当前用户可查看的门店。管理员或具备全量权限的用户返回全部有效门店；受限用户只返回其允许范围内的门店。返回字段包括 `store_id`、`store_code` 和 `store_name`。

以下接口新增可选 `store_code` 参数：

- `/api/activity-analysis/overview`
- `/api/activity-analysis/coupon-summary`
- `/api/activity-analysis/coupon-flows`
- `/api/activity-analysis/quality-issues`
- `/api/activity-analysis/coupon-type-departments`
- `/api/activity-analysis/department-tickets`

后端将所选门店条件与现有业务权限条件取交集。门店校验以服务端权限范围为准，不能仅依赖前端下拉框；传入无权限或不存在的门店时返回 `403`，不回退到全部门店。

具体门店过滤优先落在卡券日志市场字段 `tktcardfqlog.tcflmkt`，并在销售相关查询中保持与 `salehead.mkt` 的现有关联。门店编码和内部门店 ID 继续通过现有 `stores` 表及活动分析门店映射逻辑转换，兼容如门店 ID `1` 与市场编码 `601` 的对应关系。

## 数据流

1. 页面加载权限范围内的门店选项。
2. 默认不传 `store_code`，后端仅应用当前用户既有业务权限，表示“全部有权限门店”。
3. 选择具体门店后，页面所有主查询和下钻查询都携带同一个 `store_code`。
4. “活动档期券”传递 `scope=activity` 且不传 `activity_id`，复用现有逻辑汇总日期范围内所有可关联活动档期的卡券日志。
5. “非档期券”和“全部卡券”继续使用现有 `scope=standalone|all` 口径，并叠加相同门店条件。
6. 切换分析范围、门店或日期时清空已打开的部门、柜组和卡券下钻状态，避免显示旧筛选条件下的明细。

## 错误与兼容处理

- 门店选项加载失败时显示明确错误，不静默展示所有门店。
- 当前用户没有任何可用门店时，筛选框显示无可用门店，主查询返回空结果或现有权限空状态。
- “全部有权限门店”不传额外门店参数，由服务端业务权限控制范围。
- 具体门店越权或不存在时返回 `403`，页面展示接口错误。
- 后端继续接受 `activity_id`，已有外部调用方行为不变。
- 本次修改仅代表本地代码完成，不代表已部署到 `8020`。

## 测试与验收

### 前端

- 源码契约测试确认“活动搜索”和“活动档期”控件已删除，并存在“门店”筛选框。
- 确认页面不再请求活动列表，也不再向通用分析接口传递 `activity_id`。
- 确认选择具体门店后，总览、汇总、流水、质量和全部下钻请求携带相同 `store_code`。
- 确认“全部有权限门店”不传 `store_code`。
- 确认切换门店会清理旧下钻状态。

### 后端

- 门店选项只返回当前用户权限范围内的有效门店。
- 管理员可获得全部有效门店。
- 具体门店过滤叠加到现有活动范围与日志范围，不绕过业务权限。
- 无权限或不存在的门店返回 `403`。
- `scope=activity`、无 `activity_id` 时按门店与日期汇总全部活动档期券。
- `standalone` 和 `all` 范围同样正确应用门店过滤。

### 页面验收

- 在本地 `5174` 打开“销售管理 → 活动分析 → 通用活动分析”。
- 筛选区只显示分析范围、开始日期、结束日期、门店和刷新。
- 默认查看全部有权限门店；选择具体门店后所有指标、表格和下钻同步变化。
- “活动档期券”无需选择具体活动即可正常加载。
- 切换三个分析范围后，页面均无旧活动档期依赖或空白卡死状态。
