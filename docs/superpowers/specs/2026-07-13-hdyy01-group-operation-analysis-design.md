# HDYY01柜组经营分析表设计

## 目标

在 ShopView 的“销售管理 → 报表”下新增独立报表“HDYY01柜组经营分析表”。报表提供在线查询和一键导出 Excel，复用 OD0002 的日期、门店、部门筛选方式以及同一套销售数据权限，但不修改 OD0002 的接口、页面或数据结构。

报表以“机构 + 部门 + 柜组”为基础粒度，展示柜组组织属性、分类等级以及销售、成本、毛利、消费次数、客单、会员销售和储值卡销售等经营指标。查询只覆盖用户选择的本期日期范围，不提供同期或同比。

## 导航与权限

导航入口位于“销售管理 → 报表”，与“OD0002 门店销售毛利汇总表”并列，显示名称为“HDYY01柜组经营分析表”。

新增独立功能权限 `sales.hdyy01.view`，用于控制入口、在线查询和 Excel 导出。数据范围复用 OD0002 当前使用的门店、部门、柜组允许或拒绝规则：

- 门店级用户只能查看授权门店；
- 部门级用户只能查看授权部门；
- 柜组级用户只能查看授权柜组；
- 拒绝规则优先于允许规则；
- 在线查询和 Excel 导出必须使用相同的权限条件；
- 不同机构下编码相同的柜组不得合并或串数。

## 查询条件

查询条件与 OD0002 的本期条件一致：

- 开始日期；
- 结束日期，包含结束日全天；
- 门店，支持“权限内全部门店”和单个门店；
- 部门，支持“全部部门”和单个部门，选项受门店及权限范围限制。

页面不展示同期开始、同期结束或同比条件。所有查询参数使用绑定参数，不拼接用户输入。

## 在线表格

在线结果按“机构、部门、柜组”排序，使用固定表头、横向滚动、分页和合计行。字段顺序为：

1. 机构；
2. 部门；
3. 柜组编码；
4. 柜组名称；
5. 面积；
6. 楼层；
7. 一级编码；
8. 一级名称；
9. 二级编码；
10. 二级名称；
11. 等级；
12. 数量；
13. 销售收入；
14. 含税成本；
15. 毛利；
16. 消费次数；
17. 客单价；
18. 会员销售；
19. 储值卡销售。

金额在线按元展示并保留两位小数；面积保留两位小数；数量保留来源数据的有效精度；消费次数显示整数。客单价在消费次数为零时显示为空，不显示无穷大或错误值。

## 数据来源与组织关联

销售事实表为 `salegoodslist`。柜组通过 `salegoodslist.sglmfid = manaframe.mfcode` 关联，关联时同时保留 `salegoodslist.sglmarket`，确保多机构查询不混合。

`manaframe` 提供：

- `mfcode`、`mfcname`：柜组编码和柜组名称；
- `mfpcode`：上级部门编码，再关联上级 `manaframe` 取得部门名称；
- `mfyymj`：营业面积；
- `mflc`：楼层；
- `mfchr1`、`mfchr2`：分类关联编码。

组织维表在参与事实汇总前按业务编码检查唯一性。存在一对多组织映射时，不允许由连接静默放大销售金额；异常柜组进入数据质量提示。

## 分类层级与等级

新增本地报表维表 `mana_brand_hierarchy`，来源为 `BIBH.ODS_MANABRAND`。关联必须使用分类编码，不使用 `MBCNAME = CLASS3CNAME` 的名称匹配。维表字段固定为：

| 字段 | 含义 |
| --- | --- |
| `level1_code`、`level1_name` | 一级编码、一级名称 |
| `level2_code`、`level2_name` | 二级编码、二级名称 |
| `level3_code`、`level3_name` | 三级编码、三级名称 |
| `grade_code` | `MBSTR1` 原始等级值 |
| `grade_label` | 转换后的 A/B/C/D |
| `etl_loaded_at` | 本次数据装载时间 |

`level3_code` 是报表使用的唯一业务键。装载查询按 `level3.MBPID = level2.MBID`、`level2.MBPID = level1.MBID` 连接三级父子关系，并分别限制 `MBCLASS = 3/2/1`。同一 `level3_code` 如果出现多个不同父链，不得任意选取一条进入报表维表；装载应失败并报告冲突编码，避免后续关联放大金额。

层级含义固定为：

- `MBCLASS = 1`：一级编码、一级名称；
- `MBCLASS = 2`：二级编码、二级名称；
- 三级分类编码：用于连接柜组分类并取得等级；
- `MBSTR1 = '1'/'2'/'3'/'4'`：分别转换为 `A/B/C/D`。

该映射纠正 ERP 原 SQL 中 `ERJICODE` 标为一级编码、`MBPID` 标为二级编码的可疑写法。新报表只按 `MBCLASS` 和父子编码关系确定层级含义，不根据旧别名推断。

柜组通过 `manaframe.mfchr2 = mana_brand_hierarchy.level3_code` 连接三级分类，再由同一维表记录取得二级和一级分类。`mfchr2` 为空或不能匹配时，不得退回名称关联；该柜组显示“未匹配”，并进入质量提示。

## 指标口径

所有金额和数量指标均包含退货负数的冲减：

| 指标 | 计算口径 |
| --- | --- |
| 数量 | `SUM(sglsl)` |
| 销售收入 | `SUM(sglxssr)` |
| 含税成本 | `SUM(COALESCE(sgln13, 0) + COALESCE(sgln14, 0) - COALESCE(sglsupzk, 0))` |
| 毛利 | `SUM(COALESCE(sgln2, 0))` |
| 储值卡销售 | `SUM(COALESCE(sglfcard, 0))`，`sglfcard` 明确定义为储值卡销售金额 |

退货金额必须保留在上述指标中，不得为了排除退货消费次数而过滤负金额销售明细。

### 消费次数

消费次数先按“机构 + 柜组 + 核算日期 + 小票号”汇总小票净销售收入：

- 小票净销售收入大于零：计一次消费；
- 小票净销售收入小于或等于零：不计消费次数；
- 负金额退货小票的销售、数量、成本、毛利和支付金额仍保留在事实汇总中。

该分组必须包含机构和柜组，避免 ERP 原 SQL 只按 `sglmfid` 汇总导致跨机构串数。

### 客单价

客单价使用包含退货冲减后的销售收入除以正向消费次数：

```text
客单价 = 销售收入 / 消费次数
```

消费次数为零时返回空值。

### 会员销售

会员销售使用 ShopView 已有的 `salehead.hykh` 识别会员小票，不新增 `CARDXFLOG@CRM` 同步：

- `salehead.hykh` 去空格后非空的小票视为会员小票；
- 会员小票按机构和小票号关联 `salegoodslist`；
- 再按销售明细所属柜组汇总 `salegoodslist.sglxssr`；
- 会员退货的负销售金额照常冲减会员销售；
- 非会员小票不进入会员销售；
- 关联必须包含机构，必要时包含业务日期，不能只使用 `billno` 造成跨机构匹配。

## 过滤口径

HDYY01 复用 OD0002 的基础过滤规则：

1. 日期以 `salegoodslist.sglhsrq` 为准；
2. 排除 `sglwmid = '5'` 的租赁数据，空经营方式沿用 OD0002 的兼容处理；
3. 排除 OD0002 当前维护的二级部门列表；
4. 应用当前用户的门店、部门和柜组数据范围；
5. 应用用户选择的门店和部门条件。

HDYY01 不因楼层为 `00` 或分类为“其他类别区域”而直接丢弃事实行。此报表需要保留完整柜组经营结果；无法识别的楼层或分类显示“未匹配”，并进入质量提示。

## 后端结构

新增 HDYY01 专用报表服务，职责包括：

1. 构造绑定参数的查询；
2. 接收可信的销售权限 SQL 片段及参数；
3. 生成权限过滤后的销售基础集；
4. 独立计算正向消费次数；
5. 独立识别会员小票并计算会员销售；
6. 将指标按机构、部门、柜组合并；
7. 生成合计和数据质量信息；
8. 为在线接口和 Excel 导出提供同一份报表结果。

新增接口：

- `GET /api/sales/reports/hdyy01/stores`：返回权限内门店选项；
- `GET /api/sales/reports/hdyy01/departments`：返回权限和所选门店范围内的部门选项；
- `GET /api/sales/reports/hdyy01`：返回在线报表；
- `GET /api/sales/reports/hdyy01/export`：导出当前条件下的 Excel。

门店和部门选项可复用 OD0002 已验证的查询逻辑，但 HDYY01 保持独立的服务入口和权限代码，避免两个报表的响应契约互相耦合。

## Excel 输出

导出文件名为：

```text
HDYY01柜组经营分析表_开始日期_结束日期.xlsx
```

工作簿包含：

1. `明细`：与在线表格字段和顺序一致，包含合计行、冻结表头、筛选和金额格式；
2. `报表说明`：记录日期、权限范围、数据来源、指标公式、退货处理、消费次数、会员销售、租赁排除和部门排除规则。

Excel 必须复用在线报表服务的查询结果，不允许复制另一套统计 SQL。在线合计和 Excel 合计必须一致。

## 数据质量提示

接口和页面返回以下质量指标：

- 未匹配组织的柜组数及销售金额；
- 未匹配分类层级的柜组数及销售金额；
- 缺少等级的柜组数及销售金额；
- 会员小票无法匹配销售明细的数量。

分类或等级缺失不阻止报表返回。对应字段显示“未匹配”，并明确展示受影响柜组数和销售金额。组织映射一对多不得直接进入汇总，应避免金额放大并显示异常提示。

## 页面状态与异常处理

- 无 `sales.hdyy01.view` 权限：返回权限错误，页面显示“无权限查看此报表”；
- 查询成功但没有数据：返回空集合和零合计，页面显示“当前条件下无数据”；
- 结束日期早于开始日期：接口返回参数错误，页面禁止提交；
- 消费次数为零：客单价返回空值；
- 分类或等级缺失：保留该柜组，字段显示“未匹配”；
- 数据库查询失败：返回可识别错误，页面显示查询失败；
- Excel 生成失败：页面显示导出失败，不下载空文件。

## 测试策略

后端测试覆盖：

- 两个机构存在相同柜组编码时不串数；
- 退货金额冲减销售、数量、成本、毛利、会员销售和储值卡销售，但不增加消费次数；
- 小票净销售收入大于零才增加消费次数；
- 客单价分母只包含正向消费小票；
- 非会员小票不进入会员销售；
- 会员退货冲减会员销售；
- 一级、二级编码按 `MBCLASS = 1/2` 展示；
- `MBSTR1` 正确转换为 A/B/C/D；
- 权限、门店、部门过滤与 OD0002 一致；
- 分类、等级和组织缺失进入质量提示；
- 空数据返回完整响应结构；
- Excel 字段、顺序、合计和说明页正确。

前端测试覆盖：

- 菜单入口和独立权限；
- 日期、门店、部门筛选；
- 查询参数和导出参数一致；
- 表头、明细、合计、分页和横向滚动；
- 金额、面积、数量、次数和空客单格式；
- 未查询、加载中、空数据、无权限、查询失败和导出失败状态；
- 数据质量提示。

## 验收方式

上线前使用一个单门店、短日期范围与 ERP 原报表逐柜组核对：

- 销售收入；
- 含税成本；
- 毛利；
- 数量；
- 消费次数；
- 客单价；
- 会员销售；
- 储值卡销售；
- 一级、二级分类和等级。

单店核对完成后执行多门店验证：各门店分别查询的合计之和必须等于相同日期下“权限内全部门店”的合计。验收记录需要区分代码与自动化测试证据、ShopView 页面结果、Excel 导出结果和 ERP 原表对账结果。

## 不在本次范围内

- 同期、同比或自定义比较期间；
- 新建 `CARDXFLOG@CRM` 同步链路；
- 修改 OD0002 的字段、接口或页面；
- 定时报表、邮件发送或自动推送；
- 使用分类名称作为事实表关联键；
- 重构与 HDYY01 无关的销售报表代码。
