# 活动分析首期串联验收（2026-09-06）

## 交付状态

本轮完成本地代码及验证，未部署、未打包、未执行生产数据库迁移，也未替业务人员确认任何真实券资产归属。原ETL及PAPI任务配置未修改，未向ERP/CRM写入活动。

首期以601七夕（2026-08-14至08-19，B/E/H/M，ERP关联2205）验证以下链路：

候选券资产 → 人工归属确认及版本 → 活动期券流水 → 关联小票 → 品牌/供应商销售分摊；同时展示当前会员画像及独立的活动后退货观察。

这不是完整的投放、费用分摊或结算系统；年度新人券、阶段品牌券、批次管理、ERP/CRM发布、标准AI报告仍属后续阶段。

## 已实现

1. **券资产归属**：显示候选/已确认/来源变化状态。ERP档期编号仅用于规则关联，不能自动确认券归属。确认须具备整店及活动管理权限，填写核对依据，保存操作人、时间、版本、资产集合和来源指纹。源日志指向其他ERP档期或资产已归属本店其他活动时拒绝确认。
2. **并发与变更**：页面固定打开确认窗口时的预览指纹和版本；服务器重新读取核对。版本或候选变化返回409，不能默默确认后来刷新的集合。同店确认串行，版本唯一约束。已确认集合出现新增候选时不自动扩入；来源缺失单列。ERP编号改变后重新进入待确认状态。
3. **当前会员**：使用`ods.crm_member_scenes`、`crm_member_identity`、`crm_member_level`，只支持601/602/603/604及共享体系111。重复会员号、删除状态、缺本店身份、等级字典异常单列；不取最高等级、不回退旧维表、不使用607。活动时等级明确显示尚未接入历史，当前等级不得倒填历史。“档期内注册”不是首购或活动新增客，日期缺失显示未知。
4. **明细追溯**：可从券资产点击到活动期后续流水，再到唯一匹配的小票与品牌/供应商聚合销售明细。O=核销、P=退券、U/V=相应冲正；流水金额绝对值不能直接相加。品牌分摊是整票连带销售，不等于实际收券商品或费用承担。
5. **活动后退货**：按本档核销原小票号、门店、活动结束次日起至观察日，查询负净额退货。按小票去重，单独展示收入、品牌/供应商及观察截止日；不改写原活动期指标，不直接成为供应商应扣款。未关联原单和退货冲正链仍为局限。
6. **Excel**：增加券资产归属、活动期券流水、品牌供应商明细、活动后退货四个页签；报告口径包含归属版本/依据、会员来源及跨期观察限制。资产/会员/小票标识保留文本。
