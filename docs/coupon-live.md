# 秋v卡券跟进

入口：活动分析 → 秋v卡券跟进；`/dashboard?view=coupon-live`。

在“卡券汇总”中点击券种按钮或所在行，进入该券的各部门使用情况；再点击部门按钮或所在行，进入该部门的柜组使用情况。柜组页可返回当前券种的部门列表，部门页可返回卡券汇总。
部门与柜组按编码及名称区分，避免同名组织混合；柜组页展示柜组编码、名称及与部门页一致的分摊核销、退券、净连带销售、关联退货、净连带毛利。
柜组汇总由后端已授权的商品行按原有分摊口径生成，前端只筛选当前券种与部门，不新增查询、不改变金额计算或数据权限；无记录时显示空状态。

本模块只读，不依赖活动建档、券资产归属确认或新增数据库迁移。
固定门店为购物中心 601，券种 J / D / R / E / B / H / G，跟进起点为 2026-09-18。B、H、G 券沿用同一本档有效期、发放使用、部门/柜组下钻、销售退货明细、持券人今日轨迹、会员汇总和Excel导出口径。
有效期结束日从该日起有效的券日志识别；没有候选时显示无数据，多候选时要求选定，绝不自动选择其他档期。

查询开始、结束日期独立于券有效期，可选择单日（例如9月19日至9月19日），点击“查询”生效；“本档至今”恢复滚动累计。日期不得倒置、超出本档有效期或晚于北京时间今天。修改查询日期不会把提前发放的本档券排除，也不会修改券本身的有效期。

## 会员期间汇总与导出

“会员期间汇总”按所选查询期间用过指定券的持券人分组；筛选支持 J/D/R/E/B/H/G、全部跟踪券和会员卡号。消费统计也使用同一查询起止日期，包含首尾两天；例如选9月18日至18日，只显示18日的消费，不能改取系统今天。期间无可见消费的已知用券持券人仍列出，金额为零；未返回期间数据时显示不可用，不将未查询的数据置零。即使今天已超出本档有效期，仍可查询本档历史期间。

- 本人合计：所选期间小票购物会员卡等于持券会员卡的可见商品行收入，包含同期间实际退货负数，按小票/柜组/品牌/供应商粒度去重；不只统计用券小票，也不按券额分摊本人消费。
- 其他消费：本人所选期间小票中，未关联所选跟踪券的消费；筛选全部时为未关联任何跟踪券。仍可能使用其他券，不代表无优惠。退货按原小票跟踪券分类；历史查询不使用查询期结束后的冲正改变分类。
- 购物会员不同或未登记的关联净额单列，只作核查线索，不计入本人合计，不推断为本人消费。
- 点击会员行或合计金额，默认展开“其他本人消费”；可切换全部本人消费、购物会员不同/未登记、全部期间轨迹，显示时间、小票、原单、两张会员卡、部门、柜组、品牌、销售与毛利。
- 后端返回已授权的持券人队列、期间消费和独立的今日轨迹；局部权限不扩大到整店。整店账号可查询已知用券持券人的期间本人消费，即使原用券小票的商品明细尚未同步；此缺口继续显示在质量提示中。

Excel导出复用现有 Excel 库，不新增未鉴权下载接口。按当前标签、日期、券种、会员查找及下钻范围导出全部匹配行，不限制为页面的50行；刷新、鉴权失败或数据未就绪时不可导出。会员页筛选旁提供“导出会员汇总及明细”按钮；下钻会员后仅含该会员汇总及当前明细分类。

总览（未下钻部门/柜组）与持券人今日轨迹导出，也附带“会员期间汇总”和“会员期间明细”两张表，筛选与会员页当前券种、会员查找一致，不继承其他标签的单人下钻。总览主表仍为全部跟踪券，页面及导出口径分别注明会员附表券种，避免与主表混淆。销售退货、部门/柜组下钻导出仍仅含对应明细，不混入范围不同的会员表。后端未返回期间会员数据时，原视图仍可导出，口径表明确写明会员附表未提供，不以空表伪装零消费。工作簿附数据权限、筛选、会员消费统计期、实时轨迹日期、读取时间、质量缺口和计算口径；文件名包含查询起止日期（今日轨迹导出另含今日日期），会员卡及小票号以文本保存，不创建公式。

## 数据口径

- 发放：复用 `campaign.ISSUES_SQL` 的最初发券资产口径，显示截至查询结束日的本档累计，含提前发放、有效期落在本档内的券。不是所选起止日期内新增发券，也不是券余额。
- 使用：`tktcardfqlog` 的本店七种跟踪券、本档有效期，按所选查询起止日期内的业务发生日统计，首尾日期均包含。汇总、每日图表、部门、柜组和销售退货明细统一使用此窗口。
- 核销券额 = O − U；退券额 = P − V；净用券额 = 核销券额 − 退券额。基础金额取绝对值，核销和退券冲正独立计算。
- 小票关联：门店、收银机、发票号、营业日唯一匹配 `salehead`，不猜测有歧义的小票。商品销售和毛利来自 `salegoodslist.sglxssr / sgln2`。
- 关联销售：同小票七种跟踪券/持券人按有效核销金额分摊，每组商品行按分分配并保留尾差，保证不重复加整票。B、H、G 与原有券同票时统一参与分摊，不能在原有连带销售上重复增加整票收入。
- 退货：负销售小票通过 `ybillno` 归回原核销小票，即使未退券也扣销售。查询期内退货可追溯本档查询开始日前的原核销；原核销只供归属，不重复计入查询期金额。无原单号时只接受该退货票实际退券日志；有原单号但无法关联时不推断。有效期后的退货不纳入本页。
- 会员：券日志会员为持券人，小票会员为购物会员。今日轨迹覆盖所选查询期间在可见范围有效使用过指定券的持券人，其今天的购物会员小票、使用本人券的小票及其退货（今天仍需在本档内）。轨迹时间仍为今天，不随历史查询窗口改成历史轨迹；页面明确显示此区别。购物会员与持券人不同只作为待核查线索。
- 今日轨迹在多人关联同一小票时重复展示该票可见行，不能对轨迹表直接加总；销售汇总使用去重分摊链路。
- 不做同星期对比，不将关联销售当作增量销售。

## 数据权限

复用 `activity_analysis.campaign.view` 功能权限及 `load_business_scope` 当前身份（含管理员代看）的数据权限。无需新增或自动授权角色。
只读接口 `/api/activity-analysis/coupon-live` 每次重新鉴权，响应 `private, no-store`；导出仅复用该接口已授权的数据，不提供任意会员查询接口。
可选参数 `valid_to` 为本档券有效期结束日；`start_date` / `end_date` 为查询窗口，两者不能混用。未传查询窗口时默认本档起日至今天（不晚于本档结束日）。

支持门店ID/编码、部门编码/名称、柜组、供应商、品牌编码/名称、品类编码/名称、楼层；沿用允许规则 OR、拒绝优先。未知权限维度拒绝访问；无法解析的拒绝维度关闭该行访问。主档连接要求唯一映射，避免多对多放大金额。

部门等局部权限不返回整店发放人数/资产/金额。小票逐商品组过滤后才形成响应；跨范围小票券额按商品销售收入绝对值比例分摊，标为估算。持券人队列先限定为本范围用券，再按同一权限过滤期间消费和今日轨迹，不能通过会员号查看其他部门的数据。手机号不查询、不返回。

## 更新和可用性

前端在可见页面每60秒刷新，可暂停或手动刷新；读取现有ODS，不改变ERP/PAPI调度。页面区分请求时间与可见记录最新业务时间，后者不表示ETL完成水位或完整性。
同一请求使用只读可重复读事务；单条SQL超时30秒；单个明细集超过10万行报错，不截断后伪装完整报告。鉴权/刷新失败隐藏旧数据，切换身份清理查询缓存。
未唯一匹配小票、缺少初始发券、缺少商品行分开提示。局部权限不显示无权限记录的异常数量。
